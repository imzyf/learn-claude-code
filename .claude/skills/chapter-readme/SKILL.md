章节 README（`sXX_*/README.md`）当前的主要内容就是这份手动验证清单。它让读者用真实 prompt 把本章新增的机制亲手跑一遍，看见它在真实模型、真实上下文里是什么样子。读者是坐在终端前一条条粘 prompt 的人，判据要他用眼睛看终端，以及打开 `.log/`、`.transcripts/` 等目录下本次运行的输出文件。他读得懂代码也会翻日志，不用当小白带：只讲重点，指个方向就够。

写清单时不跑真实 API。期望输出照着 `main.ts` 和 `lib/` 里的字面量推，推不出来的值用占位符，不编。跑的是读者。

覆盖范围按本章机制定，不按 `main.test.ts` 覆盖与否定。`main.test.ts` 单测证明代码分支能走通，清单要让人看见终端输出、hook 时序、落盘产物和模型的实际反应。

清单正文用中文，prompt 原文、日志文案、标识符保持原样。写完的样子参考 `s01_agent_loop/README.md`。

## 步骤

新建（从 0 写一章的清单）和补充（源码改了，判据跟着改）走同一条步骤，只有第 1 步的 diff 对象不同。

1. 定位要验的那条路径。新建时 diff 本章和上一章的 `main.ts`；补充时对本次源码改动跑 `git diff`，列出被波及的小节。上游 `code.py` 和 `upstream.README.zh.md` 用来对照教学意图。
   完成条件：能用一到三句说出这条路径相对上一章（或改动前）多了什么，补充时还要点名哪几节要改。
2. 把这条路径拆成分支：正常路径、每个错误分支、边界（最新一轮不动、短输入不动、达标即停）、不在主链上的入口（模型自己调的工具、异常时的应急重试）。
   完成条件：每条分支要么进小节列表，要么在第 3 步被明确排掉。
3. 排掉与本章机制无关、又不产生可观察输出的分支，以及要等几分钟或很难凑出条件才看得到的分支。排掉的不用在正文里交代。
   完成条件：留下的每条都说得出它让读者看见本章的哪一点。
4. 每个小节配 prompt，顺着代码把这条 prompt 会走出的输出推一遍，写进 ```plaintext 块。文案去 `main.ts` 和 `lib/logger.ts`、`lib/tools.ts` 里找字面量，随每次运行变的值用占位符。
   完成条件：每条判据都是顺着代码推出来的，推不出来的值写占位符。清单正文只写读者看得见的输出，不写它出自哪个文件、哪一行。
5. 照「写法」逐条自查。补充时，没被改动波及的小节也要核一遍字面量，改动常常顺带改掉别处抄过的文案。
   完成条件：每条都过；不过的当场改。

## 写法

- 一章 4 到 7 节。每节一个断言式标题，直接写出这节要验的具体行为或机制（哪个函数、哪条分支、什么条件），不写「验证 X」「检查 X」，也不写「一句话跑遍 X」这类不点名具体行为的花哨概括。
- 开头只有三样东西：标题、`本章的机制：` 一段、启动命令。启动命令块里不写注释。
- 一节里 prompt 一到两条，每条一行原文加一行中文翻译。第二条 prompt 只是同一判据的反面时，散文说清即可，不必再配一个 ```plaintext 块。同一 session 要连续发多条 prompt 时，放进同一个 ```prompt 块，每条原文+翻译之间空一行分隔，不要拆成多个 ```prompt 块。
- prompt 里的路径按启动命令实际的工作目录写，不要假设「当前目录」等于章节目录。启动命令多数从仓库根目录跑（`pnpm dev sXX_<name>/main.ts`），工作区根就是仓库根，prompt 里涉及章节内文件要带上 `sXX_<name>/` 前缀。
- 判据写成一到两句散文：期望看到什么、这体现本章的哪一点。不写「看到 X 算过」这种判分口吻。
- 情况的描述要克制，只讲重点。一节点出一两个最能说明问题的地方就停，读者自己看得出来的细节不复述。
- ```plaintext 块只放能一眼对上的那几行，中间省略处写 `...`，可变值写 `<N>`、`<trace>`、`<模型的最终回答>` 这类占位符。整屏输出不要抄进去。
- 日志判据写成一句话，指名文件和小节：「判据在 `_transcript.log` 里的 `REQUEST` 小节」。不逐节罗列文件里有什么，也不抄日志的记录格式。不给 `grep`、`find`、`tail` 命令，也不让读者存 shell 变量，翻文件是读者自己的事。
- 除启动命令外不出现 shell 块。
- 结果依赖模型自由发挥时（比如它可能拆成多轮），补一句怎么重试，就一句。
- 最后一节写完就结束。不写补充说明、覆盖范围、清理步骤、总结。
